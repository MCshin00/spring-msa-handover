# 비교 실험 보고서: 저장소 없이 문서로 답하기

9단계의 결과다. "서비스가 떠 있고 문서가 없음" 상황에서, 저장소 없이 이 도구의 문서로 답하는 쪽(MCP, 질의응답)이 코드를 가진 에이전트(기준선)만큼 맞게, 확인 범위까지 밝혀 답하는지 최종 질문 21개로 쟀다. 조건과 채점 방식의 결정은 [결정 문서 "비교 실험"](../decisions.md#비교-실험)에 있다.

## 1. 요약

| 조건 | 맞음 | 부분 | 답하지 못함 | 확인 범위 밝힘 | 걸린 시간(중앙값) |
|---|---|---|---|---|---|
| 기준선(저장소 + Codex) | 21 | 0 | 0 | 20 (일부 1) | 71초 |
| MCP(저장소 없음 + Codex) | 12 | 9 | 0 | 21 | 49초 |
| 질의응답(`/api/ask`) | 6 | 11 | 4 | 20 (일부 1) | 4초 |

"답하지 못함"은 채점 값으로는 "틀림"이다. 채점 기준의 틀림은 핵심을 답하지 못했거나 틀린 답인데, 이 실험에서 틀림이 된 답은 모두 질의응답이 근거가 부족해 보류한 답이다. 틀린 내용을 답해 틀림이 된 답은 세 조건 모두 없다. 채점 파일(`grades.csv`, `judgments.csv`)의 값은 "틀림" 그대로다.

- **저장소 없이도 틀리지 않았다.** MCP 도구만 쓴 Codex는 틀린 답이 없었고, 확인 안 된 연결을 확인된 것처럼 말한 답도 없었다. 확인 범위를 모두 밝힌 조건은 MCP 하나다.
- **근거를 그대로 전달했다.** MCP 답의 파일 인용 580개는 모두 고정 커밋에 있는 줄이었다. 셸 명령 없이 도구만으로 답했고, 기준선보다 짧게 걸렸다(중앙값 49초, 기준선 71초).
- **저장소 밖 사실은 없다고 밝혔다.** 콘솔·메일 계정·Grafana를 묻는 질문(Q09, Q17, Q21)에는 세 조건 모두 "저장소에 근거 없음"을 밝혀 맞음이었다. 질의응답은 근거가 부족하면 지어내지 않고 보류했다(8개).
- **부족한 곳은 원인까지 찾았다.** 맞음이 아닌 답 24개 모두 원인을 붙였다. MCP 부분 9개 가운데 7개는 문서에 그 내용이 없어서였고, 빠진 내용은 오류 응답 본문, 페이지 직렬화 설정, 배포 워크플로처럼 아직 추출하지 않은 것에 몰렸다. 다음에 뽑을 것이 정해졌다.

## 2. 실험 조건

| 조건 | 답을 쓰는 쪽 | 쓰는 것 |
|---|---|---|
| 기준선 | Codex(`gpt-6-astra`, 추론 high) | 원본 저장소의 깨끗한 체크아웃(`cc43016`) |
| MCP | 같은 Codex 설정 | 원본 코드가 없는 작업 폴더와 `/mcp` 도구 5개 |

- 질문은 개발자가 실험 전에 쓰고 고정했다(`eval/questions/final.csv`, 21개). 연습 질문 2개(`tuning.csv`)로 설정과 시간 제한(5분)을 먼저 정했다.
- 기준선과 MCP는 질문마다 새 세션에서 읽기 전용으로 돌렸다. MCP 지시문은 저장소가 없다는 것과 `hotdealwave` 도구로 분석 문서를 볼 수 있다는 것만 알린다.
- 시간 초과는 없었다.

## 4. 채점 방식

한 모델의 채점을 그대로 쓰지 않았다. 두 모델이 따로 채점하고, 갈린 곳은 기준을 정해 판정했다.

| 단계 | 하는 것 | 결과 |
|---|---|---|
| 기계 검사 | 답의 `파일:줄`이 고정 커밋에 있는지 | `eval/results/final/check.csv` |
| AI 교차 채점 | 새 Codex 세션과 새 Opus 세션이 조건 이름을 A·B·C로 바꾼 세 답을 고정 커밋과 대조해 정확도·확인 범위를 매김 | `grades/codex/`, `grades/opus/`, `grades/review.md` |
| 판정 | 갈린 답과 무작위 표본을 코드와 함께 보고 정함 | `grades/judgments.csv`, `grades/judge-*.md` |
| 최종값 | 판정한 칸은 판정값, 나머지는 두 채점이 같은 값 | `grades/grades.csv` |

- AI 교차 채점에서 63칸 가운데 44칸은 두 채점이 같았고 19칸이 갈렸다(정확도 9칸, 확인 범위 16칸, 겹침 포함). 채점 한 번은 Codex 중앙값 66초, Opus 42초였다.
- 판정 기준은 개발자가 정했다. 정확도는 질문을 항목으로 나눠 코드와 맞추고, 질문이 묻지 않은 것은 요구하지 않는다. 확인 범위는 확인 안 된 것을 확인된 것처럼 말했을 때만 깎는다.
- 판정은 27칸이다.
  - 개발자가 3칸을 직접 정했다(Q04 MCP, Q06 질의응답, Q13 MCP).
  - 나머지 24칸은 새 Opus 세션이 판정하고, Codex 세션이 두 번 반박하고, Opus가 최종 의견을 낸 뒤 개발자가 승인했다. 반박으로 6칸이 바뀌었다(Q09·Q13·Q15·Q17·Q21 질의응답, Q21 MCP).
- 판정이 두 AI가 같았던 값을 바꾼 곳은 4칸이다(정확도 Q13·Q17 질의응답, 확인 범위 Q08·Q13 질의응답).

- "받은 문서에서 빠뜨림" 4개는 받은 페이지에 근거가 있었는데 답에 쓰지 않은 경우다(Q06의 락 획득 조건과 408 등).

- 칸마다의 원인과 메모는 판정한 칸은 `grades/judgments.csv`, 나머지는 `grades/causes.csv`에 있다.

## 7. 다음 할 일

1. 추출 범위를 넓힌다. 배포 워크플로, 오류 응답 본문과 Gateway의 거부 응답, 페이지 직렬화 설정을 근거 `파일:줄`과 함께 뽑는다. 모니터링 설정(Prometheus·Loki)도 같이 본다. 이번 질문에서는 Q21이 저장소 밖 사실이라 드러나지 않았지만, 저장소 안에 근거가 있는 설정이다.
2. 질의응답의 검색을 고친다. 필요한 내용이 문서에 있는데 상위 5개 절에 들지 않은 경우가 5개다. #63에서 고쳤다(9절).
3. 두 번째 대상(10단계)에 도구를 한 번 돌린다.

`repo-mcp` 결과는 채점하지 않았다. 저장소만 남은 상황은 이 실험으로 재지 않았다.

## 9. 질의응답 검색을 바꾼 뒤 다시 잰 결과(#63)

질의응답(`/api/ask`)의 검색을 BM25와 임베딩의 RRF로 바꾸고, 모델에 넘기는 칸을 상위 8개로 늘렸다. 결정과 조정용 질문 판정은 [결정 기록 "검색"](../decisions.md#검색)에 있다. 그 뒤 최종 질문 21개로 질의응답만 다시 돌려 같은 방식으로 채점했다. 기준선·MCP는 9단계 답을 그대로 썼다. 응답 근거 경로 앞부분만 지금 경로(`responses/`)로 맞춘 복사본이다.

| 질의응답 | 답함 | 보류 | 합계 | 확인 범위 밝힘 |
|---|---|---|---|---|
| 9단계(BM25 상위 5개) | 13: 맞음 3·부분 10·틀림 0 | 8: 맞음 3·부분 1·답하지 못함 4 | 맞음 6·부분 11·답하지 못함 4 | 20 (일부 1) |
| #63(RRF 상위 8개) | 12: 맞음 5·부분 7·틀림 0 | 9: 부분 4·답하지 못함 5 | 맞음 5·부분 11·답하지 못함 5 | 21 |

- 두 번 모두 답한 답에는 틀린 답이 없다(표의 "틀림 0"). 답하지 못함은 모두 근거가 부족해 보류한 답이고, 채점 값으로는 틀림이다(이번은 Q01·Q11·Q13·Q14·Q19).
- 답한 답 가운데 맞음은 3개에서 5개로 늘었다. Q04는 보류에서 답으로 바뀌었다.
- 검색은 조정용 질문에서 근거 13개를 더 찾았지만, 최종 정확도는 크게 달라지지 않았다(맞음 6→5, 답하지 못함 4→5). 남은 원인은 세 가지다. 문서에 없는 사실(추출 범위), 검색이 못 찾은 절, 조각 밖 인용을 막은 인용 검사다. Q01·Q11은 모델이 받은 조각에 없는 `파일:줄`을 인용해 인용 검사가 답을 막았다(9단계에서는 답했다).
- 비용: 시간 중앙값 4초(최대 14초, 첫 질문에서 바뀐 절의 임베딩을 다시 만듦). 입력 토큰은 넘기는 칸이 늘어 973,339(9단계 620,312), 출력 토큰은 5,404다. 질문마다 임베딩 1번과 모델 1번을 부른다.
- 채점은 Codex·Opus가 따로 했다.
  - 두 채점이 갈린 질의응답 10칸은 개발자가 정했다.
  - 두 채점이 같게 확인 범위를 깎은 8칸은 9단계 기준("확인 안 된 것을 확인된 것처럼 말했을 때만 깎는다")으로 바꿨다. 놓친 내용은 정확도에서 깎였다.
  - 기준선·MCP에서 갈린 7칸은 답이 9단계와 같아 9단계 최종값을 썼다.
  - 판정 기록은 `eval/results/final-rrf8/grades/judgments.csv`에 있다.
